# gpui-flow-composite

Toolkit-independent, bounded CPU vector isolation with locked tiny-skia 0.11.4 (BSD-3-Clause). The adapter reuses the existing Kurbo/Lyon stroke triangle producer. It does not emulate an offscreen target using GPUI `paint_layer`.

The document contract adds `Style.blend_mode` (`pass_through`, `normal`, `multiply`, `screen`) and `DisplayObject.mask` (`none`, `alpha`). Missing fields preserve legacy defaults. An alpha mask must be a direct Group child; it starts a stable z-ordered sibling run and does not draw itself. Another mask ends the previous run. Geometric picking is unchanged.

`scene_units` validates the scene and preserves the presented tree's painter order, replacing an entire isolated subtree with one `DomainSource`. `rasterize` uses an immutable domain, exact viewport/device-grid geometry, a shared `PixelBudget` and a cancellation flag. It returns only a complete premultiplied RGBA `CpuFrame`, `None` for empty/offscreen output, or an explicit error. The native SceneView consumer is the next checkpoint; this crate is independently testable without GPUI.

Supported domains: Rect (including rounded), Ellipse, Line, Polygon, Star, Path, Pen and Group. Curves use tiny-skia path primitives; multiple fills and shared centered stroke meshes retain painter order. Every object/group opacity is applied once to its entire contents. Normal groups isolate the backdrop; pass-through groups share their CPU parent; multiply/screen operate on actual pixels inside the domain. Opaque alpha-mask runs flush independent blend children to the CPU parent, matching Leafer's mask algorithm. Translucent runs composite first and apply the mask once.

Text, Image, Custom, Box and Frame inside a domain reject the complete domain. Rounded Box/Frame clips inherited from outside a domain are supported and applied once after its contents. External multiply/screen roots are rejected: native siblings, the host background, grid and UI aren't captured. Place any required background vector inside a normal Group. There are no shadow, grayscale/path/clipping mask, pixel-picking, tiling, automatic resolution reduction, wide-gamut or linear-light guarantees. Selection/layout bounds conservatively include masks and their content rather than adopting Leafer's mask bounds.

Defaults (callers can only lower these): 4096 per axis, 4,194,304 pixels per domain; 128 MiB explicit simultaneous surfaces/retained outputs; 32,000,000 conservative surface-write pixels per request; 512 nodes, 16 levels, 64 mask runs, 65,536 source points per shape, 262,144 total source points and stroke triangles, 256 gradient stops per paint, existing 32 paints per object. Full-surface accounting intentionally rejects some large multi-paint scenes even if the painted shapes are small. Coordinates must be finite/invertible and transformed control points within ±1,000,000 device pixels. Private kernel allocations and GPU memory are outside the explicit surface budget, so this is not a hard process-memory limit. A single tiny-skia operation is not preemptible; cancellation is checked between operations.

Stroke contours use the existing 0.1 local-unit approximation; rounded primitives/clips share existing bounded contours. Antialiasing and gradients need not match the previous native adapter byte-for-byte. Premultiplied output must be unpremultiplied and converted to straight BGRA exactly once at GPUI upload; never apply group opacity a second time.

References: [Leafer blend contract](https://www.leaferjs.com/ui/reference/UI/blendMode.html), [mask contract](https://www.leaferjs.com/ui/reference/UI/mask.html), [pinned upstream mask implementation](https://github.com/leaferjs/leafer-ui/blob/1e11641d3ea6b0211c83447268a90b8d58feec25/packages/partner/mask/src/index.ts). This is an independent adapter to existing kernels, not an imported Leafer renderer.
